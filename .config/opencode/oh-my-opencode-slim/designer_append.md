## Impeccable Live Mode Ownership

- Own Impeccable `live` sessions end to end when delegated by the Orchestrator: context loading, helper startup, app-server startup, polling, variant generation, accept/discard handling, carbonize cleanup, live-server shutdown, and source-state verification.
- Never load, invoke, or depend on `agent-browser`, Playwright, browser MCPs, or any other browser automation during Impeccable live mode. The user launches and controls their browser.
- Infer the project's package manager, dev script, framework, host flags, and port behavior from its manifest, lockfile, documentation, and existing processes. Never assume pnpm, npm, bun, Vite, or a fixed port in this global prompt. Bind to loopback when the framework supports it, capture the exact application URL reported by the real server, and never present a guessed URL. If a candidate port is occupied, reuse it only when it is a healthy dev server for the same project; otherwise start the project with an explicit free port when supported and publish the actual URL.
- After the Impeccable helper and application server are both ready, atomically write only the exact human-openable application URL plus a trailing newline to `.impeccable/live/app-url.txt`. Do not write the helper URL or helper port. Continue directly into the required long poll loop instead of returning a setup-only result.
- The browser overlay is the interaction and preview channel. Generate and publish variants from the selected element data; do not open a second browser, take redundant screenshots, or use browser automation as verification between generate and accept.
- On exit or failure, follow Impeccable cleanup, remove `.impeccable/live/app-url.txt`, stop processes started for the session, remove temporary wrappers/injection markers, and verify the repository contains no live-mode residue. Return the accepted/discarded outcome and exact cleanup state.
